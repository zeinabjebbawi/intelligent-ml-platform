cleaning.py

Dataset loading · statistical profiling · health score · preprocessing · auto-clean

This file's job: Everything that happens to data before training. It reads the CSV, profiles it (counts problems, detects outliers, computes correlations), scores its quality, and then cleans it step by step or all at once. It is the first file that runs after upload.
SECTION 1 — DATA LOADING (1 function)
FunctionTypePurposeInput → Output
load_data(filepath) REUSED Load a CSV file from a disk path into a pandas DataFrame. Unchanged from your course. path → DataFrame
SECTION 2 — PROFILING HELPERS (6 functions)
These 6 functions are called by profile_dataset(). You never call them directly — they are internal helpers that each compute one part of the profile.
FunctionTypePurposeInput → Output
get_column_metadata(df) NEW For every column: detect its type (numerical or categorical), count missing values, compute basic stats (mean, min, max for numbers; most common value for text). This powers the Column Passport cards. df → dict per column
detect_class_imbalance(df, target) NEW Check whether the target column has unequal class distribution. If 80% of rows are class 0, the model will be biased. Returns class counts, percentages, and an imbalance flag. Powers the "Warning: class imbalance detected" insight card. df, column → imbalance dict
compute_correlations(df) NEW Compute Pearson correlation between every pair of numerical columns. Returns a nested dict used by React to render the correlation heatmap on the Diagnose page. df → dict of dicts (col→col→value)
count_outliers_per_column(df) NEW Count outliers in every numerical column using the IQR method. Returns a dict so the health score formula knows total outlier density. Extends the course's per-column outlier detection to all columns at once. df → {col: count}
profile_dataset(df, target_column) NEW The most important function in the ML core. Calls all four helpers above and assembles everything into one large profiling dict. This runs automatically after every CSV upload. The result is stored in Dataset.profiling_result (JSONB in PostgreSQL) and is used by the health score, insight cards, and agent decisions. df → full profiling dict
compute_health_score(profiling_result) NEW Takes the profiling dict and computes a 0–100 quality score using four weighted sub-scores: Completeness (40%), Duplicates (20%), Outliers (20%), Class Balance (20%). Returns a dict with the overall score and each sub-score so the React gauge shows a breakdown. profiling dict → {overall, completeness, duplicates, outliers, balance}
SECTION 3 — MISSING VALUE HANDLERS (7 functions)
Four of these are adapted from your course. The only change: replaced inplace=True with df = df.copy(). Without this fix, the original DataFrame would be silently modified and dataset versioning would break.
FunctionTypePurposeInput → Output
count_missing(df) REUSED Return count of missing values per column. Returns a dict instead of a pandas Series for easy JSON serialization. df → {col: missing_count}
drop_missing_rows(df, subset, how) REUSED Drop all rows that contain NaN values. Optionally restricted to a subset of columns. Already returned a new df in the course version — no changes needed. df → cleaned df
fill_missing_with_mean(df, column) ADAPTED Fill NaN values in a numerical column with the column mean. Fix: replaced inplace=True with copy. Mean imputation is the default strategy for numerical columns in Smart Auto mode. df, col → df
fill_missing_with_median(df, column) NEW Fill NaN with column median instead of mean. Median is more robust when the column has outliers (the mean gets pulled toward extreme values). Used when the agent detects high outlier density. df, col → df
fill_missing_with_constant(df, column, constant) ADAPTED Fill NaN with a fixed value (e.g., 0, -1, or "None"). Fix: replaced inplace. Used when the user explicitly knows what the missing values should be. df, col, value → df
fill_missing_with_interpolation(df, column) ADAPTED Fill NaN by linear interpolation between the nearest non-missing values above and below. Fix: replaced inplace. Useful for time-series style data where values should smoothly transition. df, col → df
fill_missing_categorical(df, column, strategy, fill_value) ADAPTED Fill NaN in a text/categorical column. Strategy 'mode' fills with the most common value. Strategy 'constant' fills with fill_value. Fix: replaced inplace. Default strategy in Smart Auto mode for categorical columns. df, col → df
SECTION 4 — OUTLIER HANDLING (3 functions)
Directly from your course — no changes. They already return new DataFrames correctly.
FunctionTypePurposeInput → Output
detect_outliers_zscore(df, column, threshold) REUSED Returns a DataFrame containing only the outlier rows using the Z-Score method. A row is an outlier if its Z-Score exceeds the threshold (default 3.0). Used in profiling to show the user which rows are suspicious. df, col → df of outlier rows
remove_outliers_zscore(df, column, threshold) REUSED Remove outlier rows using Z-Score. Returns the cleaned DataFrame without those rows. The Z-Score method works best on normally distributed data. df, col → df
remove_outliers_iqr(df, column) REUSED Remove outliers using Interquartile Range. Removes rows where the value is below Q1 - 1.5×IQR or above Q3 + 1.5×IQR. More robust than Z-Score for skewed data. This is the method Smart Auto mode uses by default. df, col → df
SECTION 5 — STRUCTURAL OPERATIONS (3 functions)
FunctionTypePurposeInput → Output
drop_columns(df, columns) REUSED Remove one or more columns from the DataFrame. Used when columns have >90% missing values (useless) or when the user manually removes them. df, [cols] → df
remove_duplicates(df) NEW Remove duplicate rows. Returns both the cleaned df and the count of removed rows so the system can log "Removed 3 duplicate rows" in the transparency summary. Your course had no duplicate removal function. df → (df, count_removed)
SECTION 6 — ENCODING AND NORMALIZATION (2 functions)
Your course only covered StandardScaler for X_train/X_test after splitting. These functions apply encoding and normalization to the entire DataFrame before the split, as part of the versioning pipeline.
FunctionTypePurposeInput → Output
encode_categorical_columns(df, exclude_columns) NEW Apply LabelEncoder to all text/categorical columns, converting them to numbers. Returns the encoded df and an encoding_map (e.g., Gender: Male→1, Female→0) stored in DatasetVersion so the user can understand what was converted. df → (df, {col: {original: number}})
normalize_all_numerical(df, exclude_columns) NEW Apply StandardScaler to all numerical columns. Returns both the normalized df and the fitted scaler object. The scaler must be saved alongside the trained model because the What-If Simulator needs it to normalize new input values before making predictions. df → (df, scaler)
SECTION 7 — AUTO-CLEAN ORCHESTRATION (2 functions)
FunctionTypePurposeInput → Output
build_auto_clean_config(profiling_result) NEW Read the profiling result and decide which cleaning steps to apply. This is the "brain" of Smart Auto mode's cleaning decision. Returns a config dict: whether to remove duplicates, which missing value strategy to use, whether to remove outliers. No user input needed — it decides based on data. profiling_result → config dict
auto_clean(df, profiling_result, target_column) NEW One-call complete cleaning orchestrator. Calls build_auto_clean_config() to decide what to do, then applies all operations in sequence. Returns both the cleaned df and a human-readable summary list (the transparency log). This summary becomes the activity log shown to the user in Smart Auto mode. df, profiling_result → (cleaned_df, ["step 1...", "step 2..."])

models.py

Algorithm training · task detection · model recommendation · tournament · save/load

This file's job: Everything about training ML models. It trains individual algorithms, auto-detects which task type (classification/regression/clustering) the data needs, recommends the best algorithms with reasoning, runs the Model Tournament (all algorithms simultaneously), and saves/loads trained models for the What-If Simulator.
SECTION 1 — CLASSIFICATION TRAINING (4 functions)
KNN, Decision Tree, and SVM are directly from your course. Only Random Forest is new — it is not in the course file but is the most important classifier for production use.
FunctionTypePurposeInput → Output
train_knn(X_train, y_train, k) REUSED Train a K-Nearest Neighbors classifier with k neighbors. Directly from course. Returns the fitted model. X_train, y_train, k → model
knn_accuracy(X_train, X_test, y_train, y_test, k) REUSED Helper: train KNN with k and return test accuracy. Used inside get_elbow_data() in evaluation.py. Directly from course. X_train, X_test, labels, k → accuracy float
train_decision_tree(X_train, y_train, criterion) REUSED Train a Decision Tree classifier. criterion='entropy' (information gain) or 'gini'. Directly from course. Decision Tree also provides feature importance, which evaluation.py reads. X_train, y_train → model
train_random_forest(X_train, y_train, n_estimators) NEW Train a Random Forest classifier (100 Decision Trees combined). This is the most important new model — it almost always wins the Model Tournament for classification. Also provides the best feature importance scores. Not in your course file. X_train, y_train → model
SECTION 2 — REGRESSION AND CLUSTERING (3 functions)
FunctionTypePurposeInput → Output
train_logistic_regression(X_train, y_train) NEW Train a Logistic Regression classifier (despite the name, it is a classifier). Best for binary outcomes (yes/no, positive/negative). Simple, fast, interpretable. Good baseline model for any classification task. X_train, y_train → model
train_linear_regression(X_train, y_train) NEW Train a Linear Regression model for predicting numerical values (house prices, temperature, salary). Not in your course — your course only covered classifiers. Returns the fitted model used by evaluate_regression(). X_train, y_train → model
train_kmeans(X, n_clusters) NEW Train a K-Means clustering model. No target column needed — it finds groups automatically. Used when the user selects "Discover hidden groups" as their goal. Returns both the fitted model and the cluster labels assigned to each row. X, k → (model, cluster_labels)
SECTION 3 — INTELLIGENT MODEL SELECTION (3 functions)
These three functions are the "intelligence layer" of the model selection step. They do not train models — they decide which models to train and why.
FunctionTypePurposeInput → Output
detect_task_type(df, target_column) NEW Automatically detect whether the task is classification, regression, or clustering by analyzing the target column. If the target column has few unique values (e.g., 2 or 3) — classification. If it has many continuous values — regression. If no target — clustering. Powers the Auto Goal Detection feature. df, target_col → 'classification' | 'regression' | 'clustering'
recommend_models(task_type, profiling_result) NEW Based on the task type and dataset characteristics, return a ranked list of recommended algorithms with a plain-language reason for each. Example: "Random Forest recommended because nonlinear patterns detected and dataset has mixed feature types." This is the Model Recommendation panel on the UI. task_type, stats → [{model, reason, rank}]
get_model_by_name(algorithm_name, task_type) NEW A factory function: given a string name ("random_forest", "knn", "decision_tree"), return the correct training function. This is how the agent and the tournament call the right model without a long if-else chain. "random_forest" → train_random_forest function
SECTION 4 — TOURNAMENT AND PERSISTENCE (3 functions)
FunctionTypePurposeInput → Output
run_tournament(models_list, X_train, X_test, y_train, y_test, task_type) NEW Run all algorithms in models_list simultaneously and return a leaderboard ranked by their main metric. This is the Model Tournament feature. The leaderboard is returned as a list of dicts: [{model, accuracy, f1, rank}]. React renders this as the live leaderboard visual. models, splits → sorted leaderboard list
save_model(model, scaler, experiment_id, base_path) NEW Save the trained model and its scaler to disk using pickle. Stored as experiment_{id}.pkl. The saved model is what the What-If Simulator loads when the user adjusts sliders. Without saving, predictions would not be possible after the training session ends. model, scaler, path → file_path (string)
load_model(model_path, scaler_path) NEW Load a previously saved model and scaler from disk. Used by the What-If Simulator endpoint in FastAPI to load the model and make predictions without retraining. paths → (model, scaler)

evaluation.py

Metrics · confusion matrix · feature importance · elbow data · What-If Simulator

This file's job: Everything about measuring a trained model's performance. It computes metrics per task type, extracts feature importance, generates the elbow curve data for KNN, and handles the What-If Simulator calculations. Critically: no plt.show() anywhere — everything returns dictionaries that React renders.
Key adaptation principle: The course's evaluate_model() printed to the terminal and rendered a matplotlib heatmap. This file replaces that entirely. All functions return structured JSON-serializable dictionaries. The frontend does all rendering.
SECTION 1 — METRICS BY TASK TYPE (3 functions)
FunctionTypePurposeInput → Output
evaluate_classification(model, X_test, y_test, feature_names) ADAPTED The web-API version of the course's evaluate_model(). Returns a full dict: accuracy, precision, recall, F1-score, confusion matrix (as a 2D array, not a rendered heatmap), and feature importance. React renders the confusion matrix and charts from this dict. Nothing is printed or plotted. model, test data → full metrics dict
evaluate_regression(model, X_test, y_test) NEW Evaluate a regression model. Returns RMSE (Root Mean Squared Error), MAE (Mean Absolute Error), and R² (how much variance the model explains). None of these are in your course file — course only covered classification metrics. model, test data → {rmse, mae, r2}
evaluate_clustering(model, X) NEW Evaluate a clustering model using the Silhouette Score (measures how well-separated the clusters are, from -1 to 1). Also returns cluster sizes. Not in your course file. model, X → {silhouette_score, cluster_sizes}

get_recall(y_test, y_pred) REUSED Return recall score. Directly from course — unchanged. true labels, predicted → float
get_f1(y_test, y_pred) REUSED Return F1 score. Directly from course — unchanged. true labels, predicted → float
SECTION 3 — EXPLAINABILITY (2 functions)
FunctionTypePurposeInput → Output
get_feature_importance(model, feature_names) NEW Extract feature importance from tree-based models (Decision Tree, Random Forest). Returns a sorted list of {feature, importance_score}. Powers the Feature Importance bar chart on the Results page and the Insight Cards ("Glucose is the #1 predictor"). model, [feature names] → [{feature, score}] sorted

But instead of plt.show(), returns {k_values: [1..27], accuracies: [...], best_k: N}. React renders the elbow curve chart from this dict. splits → {k_values, accuracies, best_k}
SECTION 4 — WHAT-IF SIMULATOR (2 functions)
These two functions are what makes the What-If Simulator work. No course equivalent — they are entirely new.
FunctionTypePurposeInput → Output

Called every time the user moves a slider. Must be fast (<500ms). Returns {prediction_label, confidence, class_probabilities}. paths, slider values → {label, confidence, probabilities}

pipelines.py

Orchestration only · full pipeline · auto mode · step runner · summary generator

This file's job: pipelines.py does no math. It orchestrates. It calls the right functions from cleaning.py, models.py, and evaluation.py in the right order and returns the results. Think of it as a film director — it does not act, it tells everyone else when to act. FastAPI calls pipelines.py for every ML operation.

split_train_test(X, y, test_size, random_state) REUSED Split X and y into train and test sets. Directly from course. Lives in pipelines.py for the same reason: it is part of the training pipeline, not a data cleaning function. X, y, split ratio → X_train, X_test, y_train, y_test
scale_features(X_train, X_test) ADAPTED Apply StandardScaler to the already-split X_train and X_test (fits on train, transforms both). From course with minor adaptation: also returns the scaler object so it can be saved for the What-If Simulator. The scaler from this function is the same one predict_what_if() uses. X_train, X_test → X_train_scaled, X_test_scaled, scaler

FunctionTypePurposeInput → Output
run_cleaning_step(df, step_name, config) NEW Execute one specific cleaning operation by name. Used in Guided Manual mode where the user approves each step individually. Example: run_cleaning_step(df, "fill_mean", {column: "Age"}) calls fill_missing_with_mean. Returns (cleaned_df, description_of_what_was_done). df, step_name, params → (df, description)

Implementation Order and Why

The order is forced by dependencies. You cannot test models without clean data. You cannot evaluate without a trained model. You cannot build a pipeline without all three.

  1. cleaning.py first — no dependencies, pure pandas/scipy. Most course functions live here.
  2. models.py second — depends on cleaned/split data from pipelines helpers. Course models are fast to port.
  3. evaluation.py third — depends on having a trained model to evaluate. Course metric functions are quick rewrites.
  4. pipelines.py last — only possible when all three above work independently. It chains everything.
