## Verification approach used throughout this session

Established and reused across all 4 items above, worth continuing:
1. **Ground-truth unit tests** — synthetic data where the correct answer is
   known by construction (e.g. `y = 2.5*A - 1.2*B + noise`, so A must rank
   #1 positive, B #2 negative, noise features last), run through the real
   production code path (`training_router.py`'s own `build_model()`, not a
   hand-rolled approximation). Catches wrong-answer bugs a "did it crash"
   test never would.
2. **Live HTTP calls** against the actually-running FastAPI server
   (`urllib.request` — `requests`/`httpx` are not installed in
   `backend-fastapi\venv`) — confirms the endpoint wiring and JSON encoding
   work end-to-end, not just the Python function in isolation.
3. **Real browser** — Playwright driving the system's installed Microsoft
   Edge (`channel: 'msedge'`, `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm
   install playwright` to skip the Chromium download), screenshotted.
   Layout/CSS claims specifically need real pixel geometry
   (`getBoundingClientRect()`), not code review — jsdom has no layout
   engine.
