IntelliML — FastAPI Backend Explained

What FastAPI is, why we use it, and exactly what every endpoint does

1 — What is FastAPI and Why Do We Use It?
Simple Analogy
Django is the building manager — it handles accounts, stores files, keeps records, manages access. FastAPI is the specialized lab technician — it only does scientific computation. When the building manager needs ML analysis done, he sends the data to the lab. The lab does the heavy work and sends back results. Two separate specialists doing what they're each best at.

FastAPI is a Python web framework specifically designed for fast, asynchronous API development. It has three major advantages that make it perfect for the ML engine role:

FeatureWhat It Means For Us
Async supportML training can run without blocking other requests. Multiple users can train simultaneously.
Automatic docsGo to http://localhost:8001/docs after starting — FastAPI generates a full interactive API tester automatically. No Postman needed.
Pydantic validationEvery request is automatically validated. If React sends the wrong data shape, FastAPI rejects it with a clear error before any code runs.
SpeedFastAPI is one of the fastest Python frameworks — comparable to Node.js. Perfect for ML inference endpoints that need low latency.

How They Connect
React talks directly to BOTH backends. When React needs to upload a file or check login, it calls Django. When React needs to run ML analysis, it calls FastAPI. Django also calls FastAPI internally for some background operations (like triggering profiling after a file upload). FastAPI never writes to the PostgreSQL database directly — it returns results to React or Django, and Django handles the database writes.
3 — The Three Concepts You Need to Understand
Concept 1 — The Route (endpoint address)

A route is a URL address + HTTP method that triggers a Python function when called. In Django you had urlpatterns and views. In FastAPI, the route and the function are combined in one decorator:

# Django: separate urls.py + views.py
# FastAPI: combined in one place

@app.post("/ml/profile")
def profile_dataset_endpoint(request: ProfileRequest):
  # This function runs when React sends POST to /ml/profile
  return {"health_score": 87}
Concept 2 — Pydantic Model (request validation)

A Pydantic model is a Python class that defines exactly what shape the incoming JSON must have. FastAPI automatically rejects requests that do not match, with a clear error message. This replaces all the manual if not request.data.get('file_path') checks you would otherwise write:

class ProfileRequest(BaseModel):
  file_path: str # required
  target_column: Optional[str] = None # optional, defaults to None

# FastAPI will now:
# ✓ Accept: {"file_path": "media/.../original.csv"}
# ✓ Accept: {"file_path": "...", "target_column": "Outcome"}
# ✗ Reject: {} → 422 error: "file_path field required"
# ✗ Reject: {"x": 123} → 422 error: "file_path field required"
Concept 3 — HTTPException (error handling)

When something goes wrong, FastAPI returns a proper HTTP error code with a message. The most common ones in our system:

CodeMeaningWhen We Use It
404Not FoundCSV file path does not exist on disk
400Bad RequestUser sent an unknown step_name or invalid parameters
500Server ErrorSomething crashed inside our ML functions
422Validation ErrorPydantic rejected the request shape (auto, we don't write this)
4 — How a Request Travels Through FastAPI

Following one request from React to FastAPI and back:

1
React sends POST to http://localhost:8001/ml/profile
Body: {"file_path": "media/.../original.csv", "target_column": "Outcome"}
2
FastAPI's CORS middleware checks the origin
Is this request coming from http://localhost:5173 (React)? Yes — allowed to proceed.
3
FastAPI matches the URL to a route function
POST /ml/profile → calls profile_dataset_endpoint()
4
Pydantic validates the request body against ProfileRequest
Is file_path present? Is it a string? Yes — creates a ProfileRequest object and passes it to the function.
5
The function runs our ML code
load_data(request.file_path) → profile_dataset(df, request.target_column)
6
Function returns a Python dict
FastAPI automatically converts it to JSON and sends it back to React.
7
React receives the JSON response
{"profiling_result": {...}, "health_score": {"overall": 87, ...}}
React renders the Diagnose page from this data.
⚠️ What happens if the ML code crashes
If profile_dataset() throws any exception, the except Exception as e block catches it and returns a 500 error with the error message. React shows an error state. The server keeps running — one failed request never brings down the whole FastAPI server.
5 — Every Endpoint in main.py Explained
GET/health

The simplest endpoint. Returns {"status": "ok"}. Used to verify the FastAPI server is running before making real requests. React can call this on page load to show a "ML engine connected" indicator.

POST/ml/profile

When called: immediately after a CSV is uploaded to Django. Django sends the saved file path to FastAPI for analysis.

What it does: calls load_data(file_path) then profile_dataset(df, target_column).

Returns: the full profiling result — health score, column metadata, outlier counts, correlations, class imbalance. This is everything shown on the Diagnose page.

POST/ml/recommendations

When called: when the user reaches the Model Selection step and the system needs to show recommended algorithms.

What it does: calls recommend_models(task_type, profiling_result).

Returns: ranked list of algorithms with plain-language reasons for each recommendation.

POST/ml/clean/auto

When called: in Smart Auto mode, immediately after profiling.

What it does: calls auto_clean(df, profiling_result, target_column) which runs all 5 cleaning steps automatically. Saves the cleaned CSV to disk.

Returns: path to cleaned file, the cleaning summary list (for the transparency panel), rows before/after counts.

POST/ml/clean/step

When called: in Guided Expert mode, once per user decision. If the user has 3 recommendations and accepts all 3, this endpoint is called 3 separate times.

What it does: calls run_cleaning_step(df, step_name, config) to execute exactly ONE atomic cleaning operation.

Returns: description of what was done, row counts before and after, encoding map if encoding was applied.

Important: this endpoint OVERWRITES the file at the given path with the cleaned version. React tracks the current file path through the session.

POST/ml/train

When called: in Guided Expert mode when the user clicks "Run Training" after finishing the cleaning steps and selecting an algorithm.

What it does: calls run_full_pipeline() which runs the complete sequence → profile → clean → encode → split → scale → train → evaluate → save model.

Returns: complete results dict with all metrics, feature importance, model path, scaler path, and pipeline summary.

POST/ml/auto

When called: in Smart Auto mode — the user uploaded data and clicked "Run Everything." This one call does everything.

What it does: calls run_auto_pipeline() which auto-detects task type, runs the tournament with all recommended algorithms, and returns the complete results.

Returns: everything from /ml/train plus the tournament leaderboard and agent_decisions list.

POST/ml/elbow

When called: when the user selects KNN as their algorithm. The elbow curve helps them pick the best k before training.

What it does: runs the full cleaning + encoding + splitting pipeline, then calls get_elbow_data() to test every k value from 1 to 27.

Returns: {"k_values": [1..27], "accuracies": [...], "best_k": 7}. React renders the elbow curve chart from this data.

POST/ml/what-if/predict

When called: every time the user moves a slider in the What-If Simulator.

What it does: loads the saved model + scaler, normalizes the slider values, and calls model.predict().

Returns: predicted label, confidence percentage, all class probabilities. React updates the prediction display immediately.

POST/ml/what-if/contributions

When called: alongside /ml/what-if/predict when the user changes sliders.

What it does: loads the model and computes how much each feature contributed to this specific prediction.

Returns: {"contributions": {"Glucose": 0.45, "BMI": 0.30, ...}}. React renders the contribution bar/radar chart.

6 — Running FastAPI
# Install dependencies (one time)
pip install fastapi uvicorn python-dotenv

# Run the FastAPI server (every time you open the project)
cd C:\Users\user\ml-website\backend-fastapi
..\venv\Scripts\Activate
uvicorn main:app --host 0.0.0.0 --port 8001 --reload

# What each part means:
# main:app — look in main.py, find the object named "app"
# --port 8001 — run on port 8001 (Django is on 8080, React on 5173)
# --reload — automatically restart when you save main.py (dev mode)

After starting, open http://localhost:8001/docs in your browser. FastAPI has automatically generated a complete interactive API documentation page. You can test every endpoint directly from the browser without writing any test code.

What is Uvicorn?
Uvicorn is an ASGI server — the thing that actually listens for incoming network requests and passes them to FastAPI. Think of FastAPI as the brain and Uvicorn as the ears. Django uses Gunicorn or its built-in server. FastAPI uses Uvicorn. You never call Uvicorn's functions directly — you just start it from the terminal and it handles everything.
7 — The .env File and Environment Variables

Create a .env file inside backend-fastapi/:

# backend-fastapi/.env
DEEPSEEK_API_KEY=your_key_from_supervisor_here
ML_CORE_PATH=../ml-core
MODEL_SAVE_DIR=../backend/media/models/
DATASET_SAVE_DIR=../backend/media/datasets/

FastAPI loads this file with load_dotenv() from the python-dotenv library. The DeepSeek key is read with os.getenv("DEEPSEEK_API_KEY"). Like Django's .env, this file must never be committed to GitHub.
