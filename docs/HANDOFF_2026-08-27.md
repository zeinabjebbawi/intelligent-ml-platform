## Today's two small fixes (done, not yet browser-tested)

1. **Encoding page — scaling row blank gap.** Reported as "scaling buttons
   appear more than the number of columns" on a wide, mostly-numeric dataset
   (`customers_credit_cards.csv`, 18 columns, 1 ID column). Verified via a
   live POST to `/encoding/profile` that the backend returns exactly 18
   correct, non-duplicated columns — not a data bug. The scaling row
   structurally renders exactly one slot per column (can't exceed
   `cols.length`), but left a silent blank gap for the one non-numeric column
   instead of a placeholder, unlike the encoding row's existing "🎯 target"
   placeholder for the same situation. Added a matching "— n/a" placeholder
   for non-numeric columns in the scaling row (`Encoding.jsx`,
   `DatasetTable`'s scaling-controls block) so every column slot is visually
   accounted for.
2. **Missing Values page — charts not always split 50/50.** Root cause:
   `Cleaning.jsx`'s `ExpandableChart` component (shared by three side-by-side
   chart pairs, including "Non-null ratio per column" / "Missing value
   matrix") sits inside a `gridTemplateColumns: '1fr 1fr'` grid without
   `minWidth: 0` on the grid items — the classic CSS-Grid-vs-Recharts-
   `ResponsiveContainer` trap, where a chart can occasionally force its track
   wider than its 50% share. Added `minWidth: 0` to `ExpandableChart`'s root
   div, which benefits all three chart pairs, not just Missing Values.

Neither fix has been visually confirmed in a running browser this session (no
browser-automation tool available) — worth a quick look next time the dev
server is up.

## Diagnostic-feature standing philosophy (already saved to persistent memory)

Every column-analysis / diagnostic / insight feature in this platform must:
run all applicable rules every time a column is (re)selected; show only ONE
top-priority issue per column, never a list; use only real numbers computed
from the actual selected column's data, never templated or hardcoded; update
instantly with no loading spinner unless a computation genuinely exceeds
~200ms; action buttons call existing preprocessing functions directly and
update inline, never navigate away; badge severity colors are
red/orange/yellow/green; and never call an LLM for these insights — rule-based
statistics only. Full detail and the reasoning behind it lives in the
`diagnostic-feature-philosophy` memory file.
